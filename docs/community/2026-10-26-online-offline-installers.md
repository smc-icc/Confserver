# 在线与离线安装入口实施计划（2026-10-26）

## 目标和交付边界

用户在在线引导包和离线完整包中选择一个。现有 release/publish.sh 和 install.sh 是签名发行与安装内核；本次新增传输与制作工具，复用同一份不可变介质，不改动旧发行门禁、镜像、数据库、测试容器或客户授权。安装目标沿用 Linux/amd64，制作工具可在本机 Python/OpenSSL 环境执行。

版本（开源/专业/企业）、传输方式（在线/离线）、授权/组件升级（.smcu）分别管理。现有 root install.sh 仍要求旧原生许可，不能据此宣称已完成新版 Community 无 ICC 的首次安装或专业/企业原生配额联动。本次输出说明必须保留该限制；正式新版还需提供已适配且通过验收的签名安装内核。

## 实施步骤

1. 先添加行为测试：已签名候选介质；生成两种介质且离线字节不变；拒绝错误签名、额外文件、路径穿越、候选冒充正式；在线 HTTPS 下载、Range 恢复、错误散列和中断；安装只运行已验证入口。
2. 编写 tools/delivery/runtime.py：流式校验签名清单及文件，下载缓存和进程锁，受限解包，透传安装参数。在线元数据在生成脚本中固化，HTTPS 禁止降级，敏感查询串不输出日志。
3. 编写 tools/delivery/build-installers.py：以已有签名 .tar.gz、公钥、受信公钥指纹和 HTTPS 基地址为输入。candidate 需显式标志；production 继续调用原 release/delivery.py 的 exact-artifact VM 收据校验。输出完整离线包、轻量在线包、SHA256SUMS、操作说明，拒绝覆盖。
4. 输出一键 install.sh 在线入口。下载和 verify 无需 Docker；install 委托原安装器检查 Docker/Compose 等宿主依赖。不得自动拉取未知 Docker 安装脚本、删除卷或重新初始化现有数据库。
5. 运行真实 HTTPS 与恶意归档测试；用隔离容器的无害签名假安装器验证执行参数和重复运行，不连接 Docker socket、不挂载业务卷。测试不冒充正式主机安装验收。
6. 写用户/供应商操作手册，说明在线只需小包、离线只需大包、首次商业升级仍用 .smcu；明确交付门禁和当前授权内核限制。提交到 ConfServer Community 分支。

## 验证原则

只操作测试创建的临时目录，清理前验证目标仍在这些目录内。测试密钥独立生成，私钥不进入产物。生产签名、发行和 VM 验收证据由现有正式流程提供，不伪造或复用旧记录。没有真实合格发行输入时，交付脚本及测试结果，不能把合成包交付用户。
